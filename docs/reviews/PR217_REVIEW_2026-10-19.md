## False-pass limits (config passes the validator but is bad)
- **F1. Live facts stay post-deploy (inherent to an offline check).** These are only checked after
  `wrangler deploy` has already replaced the Worker:
  - whether the Stripe key is valid;
  - whether the Price exists, is active, is recurring and matches livemode;
  - whether the Cloudflare token is valid.

  Example: `sk_test_` + `whsec_` + `price_` (bare prefixes) passes the validator.
- **F2. Whitespace and newlines count as present.** A `" "` Cloudflare token passes, and so does a
  trailing newline on `PI_STRIPE_PRICE_ID` (`price_x\n`). This matches the bash `-n` /
  `== price_*` semantics, so it adds no new risk. A whitespace token then fails at `wrangler deploy`,
  before the Worker changes. A newline in the Price ID fails only at the post-deploy Stripe call.
- **F3. Fallback URL format not checked.** `PI_FALLBACK_API_URL: "not a url"` passes, and the
  post-deploy step does not check it either. This is outside the relayed #216 scope; noted only.
- **F4. The CLI guard fails open on a symlinked path.** Running
  `node /tmp/link.mjs` (a symlink to the script) with an **empty env** exits **0** and prints nothing.
  Node resolves the main module's real path, so `import.meta.url` ≠ `pathToFileURL(argv[1])`. The
  workflow invokes `node scripts/validate-deploy-configuration.mjs` directly, so CI is not affected
  today. A cheap hardening would be to have the test also assert that the success line is printed,
  or to use a separate entry script. Suggestion only; not pushed.
- **F5. The rules are duplicated.** The validator re-implements the bash checks, and the bash
  checks rightly remain. No test asserts they stay identical, so a future edit to one side can
  drift silently.
- **F6. The CLI-level check is wired into CI only.** `npm run test:v1.02` and
  `test:release:v1.02` in `package.json` do not include the focused test. A local release run
  skips it. PR Core runs it only when the PR touches `worker/**`, `package.json` or
  `pi-v102-pr-core.yml`.
