## Fix
- A verified `ci` item needs `subject_sha`: a full, lowercase 40-hex sha. Only passing runs whose `head_sha` equals it
  count.
- The reasons are `ci_claim_missing_full_subject_sha` and `ci_run_head_sha_mismatch(subject:…,runs:…)`.
  The existing `ci_run_not_completed_success(…)` is still reported first when no run passed.
- Matching never uses short shas, urls or claim text.
- Contradiction, for CI only:
  - a failing run on a **different** full sha no longer demotes;
  - a failing run on the subject sha demotes;
  - a failing run with no usable `head_sha` still demotes.
- New trust-limit line; the doc is updated.
- Source, test and live/session classification is unchanged. The regression asserts `subject_sha` does not affect
  test or source items.

## Schema choices to confirm (ambiguous)
